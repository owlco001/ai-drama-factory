## 1. 产品概述

### 1.1 一句话定位
「Agent团队」是一款完全离线运行的安卓应用，由本地大模型（llama.cpp）驱动一个层级式多Agent系统：1个协调调度Agent管理5个专业子Agent，协同完成用户的复杂任务。

### 1.2 背景与价值
- 隐私优先：所有推理在端侧完成，无云端依赖、无数据上传。
- 可视化的多Agent协作：用户能看到"团队"如何分工、传递消息、完成任务链路。
- 差异化：区别于单对话式助手，提供任务分解→分派→执行→校验的完整链路展示。

### 1.3 核心架构概念
- **协调Agent（Coordinator）**：接收用户请求，拆解为子任务，按DAG分派给子Agent，汇聚结果。
- **5个专业子Agent**：
  1. 检索Agent（本地知识/文档检索）
  2. 分析Agent（推理、归纳、对比）
  3. 创作Agent（文本生成、改写）
  4. 工具执行Agent（调用白名单内工具）
  5. 校验Agent（结果核查、格式与事实校验）
- **每个子Agent独立配置**：System Prompt、独立记忆、工具白名单。
- **内部消息总线**：Agent间通过结构化JSON消息通信。
- **MVP范围**：单会话、串行调度、三层记忆、工具白名单、任务DAG展示。

## 2. 目标用户

| 用户群 | 描述 | 核心诉求 |
|---|---|---|
| 主要：隐私敏感的效率用户 | 懂技术的安卓用户，不愿把笔记/文档传云端 | 离线可用、数据不出设备 |
| 主要：AI爱好者/开发者 | 关注多Agent架构，想观察Agent协作过程 | 可视化任务链路、执行日志、@点名调试 |
| 次要：移动办公轻量用户 | 无网络环境（飞行模式、野外）下需要写作/分析辅助 | 断网可用的创作与分析能力 |

**前提条件**：中端及以上安卓机（建议8GB RAM），能接受本地模型的推理速度与质量上限。

## 3. MVP功能清单

优先级定义：P0=MVP必须；P1=重要但可延后到v1.1；P2=远期。

### P0（必须有）

| 编号 | 功能 | 说明 |
|---|---|---|
| F01 | 本地模型引擎集成 | 内置llama.cpp推理引擎，支持加载GGUF模型；内置模型下载/导入入口（下载文件本身属外部行为，App只管加载） |

| F05 | 任务DAG展示 | 图形化展示Coordinator生成的任务依赖图及各节点状态（待执行/执行中/成功/失败） |

| F08 | @点名子Agent | 用户在输入框用"@检索"等语法直接指定某子Agent执行 |

## 4. 用户故事

1. **US1（隐私用户·离线分析）**：作为一名隐私敏感用户，我在飞行模式下让App分析一份本地文档的要点，以便不联网也能获得结构化摘要——我希望看到检索Agent取文、分析Agent归纳、创作Agent成稿的完整DAG链路。
2. **US2（开发者·调试）**：作为AI爱好者，我@点名"校验"Agent复核上一轮创作Agent的输出，以便定位幻觉内容；我希望日志中能看到两个Agent间的原始JSON消息。
3. **US3（效率用户·复杂任务）**：我提出"帮我写一封基于这份会议纪要的跟进邮件"，Coordinator将其拆为检索→分析→创作→校验四步，我能在DAG图上实时看到每个节点的状态流转。
4. **US4（工具安全）**：当创作Agent试图调用未在白名单内的工具时，系统拒绝该调用并在日志中提示，以便我确信App不会越权操作我的手机。
5. **US5（长任务恢复）**：一次多步任务中途App被杀后重新打开，我能从任务级记忆恢复上下文并继续或重跑剩余节点，而不必从头开始。（P1候选，见待确认问题Q6）
6. **US6（资源受限）**：我在8GB RAM手机上使用时，App能自动选择合适的量化模型与上下文长度，保证后台不被系统杀死、其他App仍可正常使用。
7. **US7（透明可控）**：任何时刻我可以查看某个子Agent的独立记忆内容和当前System Prompt，以便理解它"为什么这么做"。

## 5. 非功能需求

### 5.1 性能与内存约束（目标机型：中端安卓机，8GB RAM）

| 指标 | 要求 |
|---|---|
| App内存峰值 | ≤ 2.5GB（含模型）；前台常驻 ≤ 3GB，避免触发LMK |
| 模型要求 | 默认推荐7B级别Q4_K_M量化GGUF（约4GB）；支持1.5B–8B范围 |
| 首token延迟 | 中端SoC上 ≤ 5s（预热后） |
| 生成速度 | ≥ 5 token/s（7B Q4, 4线程基准） |
| 冷启动时间 | ≤ 4s 到主界面（模型懒加载） |
| 串行调度开销 | 单次Agent间消息往返额外延迟 ≤ 200ms |
| 存储 | 安装包 ≤ 100MB（不含模型）；模型存放于用户可见目录 |
| 崩溃率 | 会话崩溃率 < 0.5%；OOM导致的进程死亡需可从任务记忆恢复 |

### 5.2 其他非功能需求

- **隐私**：零网络数据上传（模型下载除外，且需显式用户确认）；日志仅存本地。
- **可靠性**：单Agent异常不得导致整个会话崩溃，Coordinator应标记失败节点并可重试。
- **兼容性**：Android 10（API 29）+，arm64-v8a。
- **电池**：连续推理30分钟，机身温升与耗电控制在同类本地推理App水平。
- **可用性**：中文界面为主；DAG图、团队面板在5.5–6.7寸屏均可用。

## 6. 明确排除项（Non-goals）

以下内容**不在本产品范围**（来源T001 + 推导补充）：

1. 并行推理/多Agent并发调度（MVP仅串行）
2. 自定义子Agent编辑器（角色固定为6个）
3. 云端模型/云混合路由
4. iOS/Web/桌面版本
5. 多模态输入（图片、语音）——MVP纯文本
6. 在线检索（联网搜索）——检索Agent仅限本地知识库
7. 多用户/账号体系/云同步
8. Agent间自由组网（拓扑固定：星型，Coordinator为中心）

## 7. 待确认问题（需求歧义与风险）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| Q1 | "三层记忆"具体指哪三层？（本文假设：会话短期/任务级/全局长期）持久化策略、容量上限、淘汰机制未定 | 高 | 与架构Agent对齐后补充附录 |
| Q2 | MVP工具白名单具体包含哪些工具？涉及敏感权限（文件、剪贴板）的范围与审批方式未定 | 高 | 首版建议仅：计算器+剪贴板读 |
| Q3 | 模型分发方式：引导用户自行下载GGUF，还是App内置下载器（涉及网络权限与"无云端依赖"表述冲突） | 中 | 建议App不含下载功能，提供文档指引 |
| Q4 | 目标最低机型是8GB还是更低？"中端机"定义未量化（SoC/RAM下限） | 中 | 建议P0支持6GB RAM + 1.5B~3B模型降级档 |
| Q5 | 校验Agent失败/低置信时的处理策略：自动重试、询问用户、还是仅标注？未定 | 中 | MVP建议仅标注+日志 |
| Q6 | US5的任务中断恢复是否属于MVP？T001未提及 | 中 | 建议列为P1 |
| Q7 | @点名语法与自然语言指令冲突时的解析规则未定 | 低 | MVP：以@开头即视为点名 |
| Q8 | 本地知识库的数据来源与导入格式（TXT/PDF/Markdown？）未定，直接影响检索Agent设计 | 高 | 需求评审时确认 |
| Q9 | 性能指标（首token 5s、5 tok/s）为经验值，需在真实中端机上实测校准 | 低 | 冒烟测试阶段验证 |

**风险摘要**：最大风险是端侧算力与7B模型质量的落差（体验风险），其次是内存约束下的稳定性（OOM）。建议尽早做真机性能冒烟测试。

## 8. 成功指标（MVP验收参考）

- 核心链路（提问→DAG展示→至少3个Agent串行完成→结果返回）端到端成功率 ≥ 90%
- 8GB参考机型上连续运行30分钟无OOM崩溃
- 用户可在面板/日志/DAG中追溯任意一条Agent消息
