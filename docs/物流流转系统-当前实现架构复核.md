# 物流流转系统当前实现架构复核

更新时间：2026-09-13
复核范围：`logistics-android/`、`material-flow-backend/`
复核角色：架构 Agent（仅写入 `docs/` 与 `tasks/`，未修改业务源码）

## 1. 结论

当前实现达到 **M1 早期骨架 / Mock 联调准备**，未达到生产 APP 或生产后端验收标准。

已具备：

- 独立 Android 工程目录：`logistics-android/`
- 独立 FastAPI 后端目录：`material-flow-backend/`
- Android Launcher Activity、Compose 页面、Room 数据库声明
- 后端 SQLite 初始化、登录、扫码解析、库存查询、订单物料状态、入库/出库申请、审批、执行、用户和审计路由
- 后端 `clientOperationId` 创建幂等的初步实现

尚未具备：

- 可证明的 Android Debug APK 交付记录
- 真机或模拟器安装运行记录
- Room 正式编译器配置与离线队列真实接入
- CameraX/工业扫码枪适配
- WorkManager 自动同步
- 安全 token 存储、刷新、退出和失效策略
- 完整的库存版本校验、审批/执行隔离和库存事务测试
- 生产 HTTPS、反向代理、数据库备份和部署验证

## 2. 模块图（文字版）

```text
[Compose UI / MainActivity.kt]
          |

          |
          v
[Domain UseCase]
          |
     +----+-------------------+
     |                        |
[Remote Repository]     [Local Repository]
     |                        |
[Retrofit API]           [Room DB]
     |                        |
     +-----------+------------+
                 v
        [Sync Coordinator]
                 |
        [WorkManager Worker]
                 |
                 v
 [FastAPI Routes / Service Layer]
                 |
     [Auth / Inventory / Workflow]
                 |
              [SQLite]
```

依赖方向必须固定为：

```text
UI → ViewModel → UseCase → Repository interface
Repository implementation → Retrofit / Room / Platform adapter
Sync Worker → UseCase / Repository
```

禁止 Composable 直接创建 HTTP 连接、拼接 JSON 或持有 access token。

## 3. 当前实现核对结果

### 3.1 Android

- `MainActivity.kt` 同时承担页面、角色切换、网络请求、JSON 解析、内存队列和业务状态，违反分层要求。
- `API_BASE` 硬编码为 HTTP 地址；生产环境必须由 `BuildConfig`/安全构建参数注入，且只允许 HTTPS。
- 登录密码字段未设置密码输入遮罩；token 只存在 Composable 内存，进程重启即丢失。
- 当前只有料号库存、订单状态和入库申请路径；出库、调拨、盘点、库位绑定、异常凭证、审批页面尚未形成完整客户端闭环。
- 队列是 `mutableStateOf(listOf<QueueItem>())`，不是 Room 持久化；“立即同步”只是把状态改成“同步成功”，没有调用后端。
- `LogisticsDatabase` 声明了 DAO，但 `app/build.gradle.kts` 未配置 Room compiler/KSP，不能把“有 Entity/DAO 文件”视为 Room 已接通。
- 未发现 Hilt、Navigation Compose、Retrofit、CameraX、WorkManager 的完整接入配置。
- 当前角色切换由客户端任意修改，仅能作为演示；生产权限必须由后端授权结果控制。

### 3.2 后端

- 已有 SQLite 表和主要路由，适合作为开发期最小服务。
- `hash_password` 使用 `scrypt`，与冻结契约要求的 Argon2id 不一致；上线前必须统一为 Argon2id。
- 登录失败没有实现“连续 5 次失败锁定 15 分钟”。
- 登录响应没有 `refreshToken`，退出/刷新接口也未形成完整会话生命周期。
- 扫码返回 `ORDER_NO`、`LOGISTICS_NO`，与冻结契约的 `PRODUCTION_ORDER`、`FLOW_NO` 不一致；客户端当前也发送 `ORDER_NO`。
- `execute_transfer` 未使用请求 item 中的 `expectedInventoryVersion` 做条件更新；当前版本自增不能单独证明乐观锁生效。
- 执行库存更新后未同步更新 `inventory` 分库位数量，物料汇总与库位明细可能漂移。
- 审批接口未阻止同一用户审批并执行同一单据。
- `Transfer.items` 使用 `list[dict[str, Any]]`，接口字段和类型不够精确；应使用 Pydantic 嵌套模型。
- 部分路由使用裸 `dict[str, Any]`，缺少统一错误结构、traceId/requestId 返回和字段约束。
- `evidenceIds` 使用可变默认值 `[]`，应改为 `Field(default_factory=list)`。
- 初始化数据、数据库路径和上传目录适合开发环境，不足以证明生产部署完成。

## 6. 技术选型及理由

- Kotlin + Jetpack Compose：适合 Android 8.0+，减少 XML 页面维护成本。
- Hilt：统一依赖注入，避免 Activity/Composable 直接构造网络和数据库对象。
- Retrofit + kotlinx.serialization：声明式 HTTP API 和类型安全 DTO，替代手工 `HttpURLConnection`/`JSONObject`。
- Room + SQLCipher/Keystore 加密封装：离线队列可事务持久化，敏感 payload 受保护。
- WorkManager：网络恢复后可靠执行有限重试，适合 8GB 中端 Android 的后台约束。
- CameraX + `ScannerRepository`：相机能力与工业扫码枪适配解耦。
- FastAPI + Pydantic：接口类型校验、OpenAPI 文档和低部署成本。
- PostgreSQL（生产）/SQLite（开发）：生产并发、事务和备份能力更可靠；SQLite 仅保留为单机开发模式。
- Argon2id：符合密码存储契约，降低离线破解风险。

## 7. 资源与性能约束

- 本地离线队列按页读取，默认 pageSize 50，单批同步最多 20 条，并发最多 2。
- 图片凭证客户端压缩到最长边 1920px、JPEG 质量 80，单张不超过 2MB，单次最多 5 张。
- 扫码结果去重窗口 1500ms，禁止在 UI 线程执行网络、数据库和图片压缩。
- 订单和审计列表必须服务端分页，不在客户端聚合全量数据。
- WorkManager 使用网络约束和指数退避，自动重试最多 5 次。

## 8. 生产阻塞与验收门槛

当前评审结论：**暂不允许合并主分支或宣称生产可用**。

必须全部满足：

- Android `assembleDebug` 成功，APK 路径、字节数、SHA-256 有真实记录。
- Android 单元测试、Room 测试、Repository MockWebServer 测试通过。
- 无网络/进程被杀后，离线队列可恢复且重试不产生重复单据。
- 后端扫码枚举与 API 契约一致。
- 库存版本冲突返回 409 且不改变库存；重复 `clientOperationId` 返回同一业务结果。
- 审批和执行权限、同人隔离和审计字段验证通过。
- HTTPS、环境变量、日志脱敏、数据库备份和健康检查完成。
- 至少一台 8GB 中端 Android 真机完成连续扫码 30 分钟和断网恢复测试。
