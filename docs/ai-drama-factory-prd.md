## 1. 产品概述

### 1.1 一句话定位
「AI短剧工厂」是一款安卓应用，把 pavo-drama 的端到端AI短剧生产管线（小说→剧本→资产→分镜→视频→成片）移植到手机端：**编排逻辑在本地，生成能力走云端API**（Agnes/PavoAPI 等），用户从导入一部小说开始，最终在手机上拿到竖屏短剧成片。

### 1.2 背景与价值
- **移动化生产**：桌面端管线已实战验证（《莽途》ch001 全链路24镜出片），但依赖PC与命令行；移动端让作者随时随地建项目、审资产、盯渲染。
- **人机分工合理**：不做本地大模型推理——文本生成（剧本/分镜/审计）走云文本模型（agnes-2.5-flash），图像走 agnes-image-2.1-flash，视频走 agnes-video-v2.0；App只负责编排、闸门、状态机与展示。中低端手机也能用。
- **开放模型生态**：视频模型供应商可配置——预置 Agnes/PavoAPI（接口已验证），架构留供应商适配器接口，未来扩展可灵/即梦/Vidu等；用户自带 API Key。

### 1.3 核心流程概念（移植自 pavo-drama）
```
项目 ──> 小说导入(scan-novel) ──> 资产库(角色6pose包/场景/道具 + 两层质量闸门G1/G2)
     ──> 资产人工评审(review) ──> 剧本生成(writer, 吃原著铁律)
     ──> 分镜编译与六铁律校验(storyboard gate) ──> 渲染队列(首尾帧keyframes模式,
        异步提交+轮询+断点续传checkpoint) ──> 成片组装(assemble)
```
关键机制照搬：结构闸门失败即阻断、跨镜锁脸（CharacterDNA + I2I绑定）、道具母图合成引用、断点续传状态机（pending→submitted→completed）、视频提交限速门。

## 2. 目标用户

| 用户群 | 描述 | 核心诉求 |
|---|---|---|
| 主要：网文作者/短剧创作者 | 有小说原著，想低成本试做短剧样片的个人创作者 | 小说一键变剧本；角色形象不漂移；按集推进 |
| 主要：AI内容工作室从业者 | 用Agnes等平台Key批量产出的半专业用户 | 多项目管理、渲染队列稳定跑完一整集、成本可见 |
| 次要：AI视频爱好者 | 已有各平台API Key，想体验端到端管线的玩家 | 自选模型供应商、填自己的Key即可上手 |

**前提条件**：Android 10+ 手机，能联网；用户自备视频/文本模型平台的API Key并接受按量计费。

## 3. MVP功能清单

优先级定义：P0=MVP必须；P1=重要但可延后到v1.1；P2=远期。

### P0（必须有）

| 编号 | 功能 | 说明 |
|---|---|---|
| F01 | 项目管理 | 创建/删除「短剧项目」（对应一个run_dir）：项目名、风格预设（era时代红线块）、集数规划；项目列表页 |
| F02 | 小说导入 | 粘贴TXT或选本地文件 → 云文本模型两轮提取角色/场景/道具 → 生成可编辑的spec草案 |
| F03 | 资产库 | 角色（1024x1024 六pose资产包）/场景/道具卡片的生成、浏览、单卡重生成；G1文件级硬校验 + G2多模态评分两层闸门，rejected自动重试并记录原因 |
| F04 | 资产评审画廊 | 缩略图画廊逐卡勾选 通过/重生成，全部通过后才允许进入渲染（花钱前的人工闸门）；勾选状态持久化 |
| F05 | 剧本生成分镜 | writer按原著节拍表逐集生成剧本 → storyboard编译 + ToonFlow六铁律机器校验，任何error阻断渲染并给出修复建议 |
| F06 | 视频模型供应商设置流 | 见 §4.3 详细设计：选供应商→填Key→测试连通→保存；Key存Android Keystore加密存储；适配器接口预留可灵/即梦扩展 |
| F07 | 渲染队列 | 逐镜异步任务队列：POST /videos提交（keyframes首尾帧模式，generate_audio原生中文配音）→ GET轮询；限速门（默认≥120s/次提交）；每镜状态机 pending→submitted(记video_id)→completed/failed/blocked |
| F08 | 断点续传 | checkpoint本地持久化；App被杀/断网后恢复时，已提交未完成的镜先re-poll已知video_id，绝不重复提交重复付费 |
| F09 | 后台保活与进度通知 | Foreground Service承载轮询；系统通知栏常驻显示「第X集 · 12/24镜完成 · ETA约35分钟」；完成/失败/预算超限各自通知 |
| F10 | 成片预览与导出 | 镜片段落拼接预览、导出MP4到相册/分享 |
| F11 | 预算闸门 | 项目级视频生成预算（条数/金额估算），超限暂停队列并提示确认 |

## 4. 重点设计

### 4.1 管线阶段的产品化呈现

底部Tab + 阶段进度条双导航，阶段间设硬性门槛：

| 阶段 | 页面 | 进入条件（Gate） |
|---|---|---|
| ① 项目 | 项目列表/详情 | — |
| ② 小说导入 | 导入向导 + spec草案编辑 | 文本模型连通 |
| ③ 资产库 | 卡片网格（角色/场景/道具分组）+ 单卡详情 | spec已确认 |
| ④ 资产评审 | 评审画廊（全过才放行） | 资产生成完毕 |
| ⑤ 分镜编辑 | 每集剧本 + 分镜表 + 六铁律校验结果面板 | 评审通过 |
| ⑥ 渲染队列 | 任务卡片列表（镜号/状态/video_id/耗时）+ 总进度 | 校验通过 + Key有效 + 预算未超 |
| ⑦ 成片 | 播放器 + 导出/分享 | 全部镜completed |

顶部常驻阶段进度条（①→⑦），当前阶段高亮；被闸门拦下时点击进度条直达拦截详情。

### 4.2 视频模型供应商设置流

```
设置 → 视频模型
  1) 选择供应商：[Agnes/PavoAPI（推荐·已验证）] [自定义OpenAI兼容] （可灵/即梦置灰"即将支持"）
  2) 填写 API Key（密码框，粘贴校验格式）
  3) 「测试连通」：发一次最小成本请求（列模型或1张测试图），展示延迟与结果
  4) 选择具体模型（如 agnes-video-v2.0）+ 高级参数（generate_audio开关、分辨率、时长）
  5) 保存 → Key写入 Android Keystore 加密存储，界面永不回显明文
```
- **供应商适配器接口**（架构约束）：`interface VideoProvider { submit(shot): taskId; poll(taskId): status/url; listModels(); testConnection() }`，内置 `AgnesProvider` 实现（POST /videos + GET /agnesapi?video_id=），新供应商只需新增实现类。
- 文本/图像模型同样走Key配置，MVP默认随Agnes同一Key。
- Key失效（401）时全局横幅提示并引导回设置页，队列自动暂停不烧重试。

### 4.3 渲染队列的后台保活与进度通知

- **Foreground Service**：进入渲染即启动前台服务（常驻通知，符合Android后台限制），持有队列执行器；App进程被杀后服务仍续跑；服务也被杀则下次启动读checkpoint续传（F08）。
- **限速与退避**：提交间隔默认120s（对齐Agnes 1RPM限速，可配）；429立即长退避不快重试；5xx指数退避上限3次。
- **通知策略**：
  - 常驻：进度通知（每完成N镜更新，含ETA）
  - 事件：单镜失败（可点进重试）、整集完成（可点播放）、预算超限（需确认才能继续）
- **电池/网络**：提供「仅Wi-Fi渲染」开关；Doze模式下靠Foreground Service豁免持续轮询，轮询间隔自适应（submitted初期30s，10分钟后降为60s）。

## 5. 用户故事

1. **US1（网文作者·导入）**：我把自己20万字的小说TXT导入，App几分钟内提取出主角/场景/道具草案让我微调，以便不用手写spec就能建库。
2. **US2（创作者·审资产）**：资产生成后我在画廊里逐个看角色的6个pose图，把两张有杂斑的点「重生成」，其余勾「通过」，全部通过后App才允许我花视频额度。
3. **US3（爱好者·配Key）**：我注册了Agnes账号，在设置里选「Agnes/PavoAPI」、粘贴API Key、点「测试连通」看到绿色成功提示后保存，然后就可以开渲染了。
4. **US4（工作室·挂机渲染）**：晚上我点了「渲染第1集」锁屏睡觉，手机通知栏整夜显示进度「14/24镜」，早上收到「第1集渲染完成」通知，点开直接预览成片。
5. **US5（断点恢复）**：渲染中途手机没电关机，充上电重新打开App，队列从checkpoint恢复——已出片的12镜直接跳过，第13镜先去轮询已提交的video_id而不是重新花钱提交。
6. **US6（成本控制）**：我给项目设了50条视频的预算上限，渲染到第50条时App暂停队列弹窗让我确认是否加量，避免Key被意外刷爆。
7. **US7（闸门透明）**：第7镜一直没进渲染队列，我点开它看到「被分镜闸门拦截：台词与剧本不一致」，并能查看具体diff，修完重新校验通过后自动入队。

## 6. 非功能需求

### 6.1 移动端核心约束（云端异步生成）

| 指标 | 要求 |
|---|---|
| 断点续传 | 任意时刻进程被杀，重启后不丢失已提交任务的video_id，不产生重复付费提交；恢复成功率100%（有checkpoint即必恢复） |
| 后台存活 | Foreground Service下整集（24镜×~2分钟/镜≈50分钟）渲染期间不被系统回收；被杀后可完全恢复续传 |
| 轮询效率 | 自适应间隔（30s→60s）；后台8小时累计轮询流量 ≤ 5MB |
| 通知 | 进度通知更新频率 ≥ 每5分钟一次；完成/失败/预算事件必达 |
| 网络 | 弱网/断网时队列暂停并明确标注「等待网络」而非报错失败；网络恢复自动续跑 |
| 存储 | 安装包 ≤ 80MB；成片缓存于应用专属目录，提供清理入口；单集成片约200–500MB需提示剩余空间 |
| 安全 | API Key仅存Android Keystore加密区；日志脱敏（不打印Key/完整prompt中的敏感内容） |
| 兼容性 | Android 10（API 29）+，arm64-v8a；中端机（4GB RAM）流畅操作UI（生成均在云端，端侧无算力门槛） |
| 崩溃率 | 主流程崩溃率 < 0.5%；任何单镜异常不得导致整个队列崩溃 |

### 6.2 其他
- **隐私**：小说原文与剧本会上传至所选云模型平台，首次使用前需明示告知并获得同意。
- **可用性**：中文界面为主；渲染队列页在一镜一条卡片的信息密度下保持可滑动不卡顿。
- **合规**：生成内容由用户对其平台账号行为负责；App内提示平台内容政策链接。

## 7. 明确排除项（Non-goals）

1. **本地大模型推理**——文本/图像/视频生成都走云API，端侧只做编排（与「Agent团队」App的根本区别）
2. iOS/Web/桌面版本
3. 本地视频剪辑/时间线编辑器（MVP只有镜序拼接与成片预览）
4. 内置TTS声纹克隆（GPT-SoVITS/Demucs等重型音频栈不上移动端，换声列P1另评估云方案）
5. 多用户/账号体系/社交功能
6. MVP阶段的第三方视频供应商（可灵/即梦等，仅留适配器接口，见Q3）
7. 平台代充值/内购计费——Key与费用完全归用户自有账号

## 8. 待确认问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|

| Q5 | 成片组装在端侧FFmpeg做还是也上云？端侧拼24段448x832 MP4的性能与内存压力待测 | 高 | 冒烟测试端侧FFmpegKit拼接，不行改云组装或分段导出 |
| Q6 | 文本模型是否允许用户单独指定不同供应商（如DeepSeek写剧本）？ | 低 | 架构上文本/图像/视频三通道独立适配器，MVP共用一个Key |
| Q7 | Foreground Service在国产ROM（MIUI/鸿蒙等）激进杀后台下的兜底策略（引导加白名单？） | 中 | 设置页提供各ROM保活指引 |
| Q8 | 资产评审是否支持多人协作（如工作室老板终审）？ | 低 | 列P2云同步范畴 |
| Q9 | generate_audio原生配音的语言漂移问题（pavo实测非首镜易跑英文），App层是否加中文指令强制注入？ | 中 | 默认注入中文配音指令prompt，作为产品默认行为 |

**风险摘要**：最大风险是Q1（移动端直连Agnes的可行性与稳定性），其次是Q5（端侧成片拼接性能）。建议立项后第一周做两个技术冒烟：真机直连Agnes全链路、FFmpegKit端侧拼接24镜。

## 9. 成功指标（MVP验收参考）

- 核心链路（导入小说→建资产→评审→渲染一集24镜→导出成片）端到端成功率 ≥ 85%
- 渲染中断恢复：杀进程重启后零重复付费提交
- 整夜锁屏渲染（≥50分钟）完成率 ≥ 90%
- 从填Key到首次成功出片的新手时长 ≤ 30分钟
