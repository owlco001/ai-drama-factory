## 一、背景与目标

「AI短剧工厂」当前 v1.3.0 已具备：项目/剧集管理、AI资产提取、AI分镜、渲染队列（断点续传/预算熔断），但**全流程需人工逐页点击**，且渲染队列产出单镜 mp4 后没有"合成本集成片"能力（成片库页是半占位：只能分享缓存里已存在的文件）。

本版本三个目标：
1. 首页分化「AI 全托管」「人工模式」两个入口——AI 模式用户只给剧本，其余环节全自动 + 流式进度；
2. AI 模式的文本模型可选 DeepSeek（OpenAI 兼容），沿用现有 Provider 三通道架构；
3. 整集渲染完成后一键合成单一成片，落成片库并可播放/分享。

## 二、现状梳理（代码勘察结论）

| 模块 | 现状 | 差距 |
|---|---|---|
| DramaApp.kt | 底部导航 6 页（项目/剧集/资产/分镜/渲染/成片）+ 设置；AppNavState 传递当前项目/集 | 无"模式"概念，无 AI 托管入口页 |
| SettingsPage.kt | 视频供应商选择（ProviderRegistry）+ 自定义 OpenAI 兼容模型 + API Key/测试连通 | 只有**视频**通道选择，无**文本模型**独立选择（DeepSeek 无处安放） |
| LibraryPage.kt | 列出各集完成度 done/total；导出分享读 cacheDir/$epId.mp4，不存在则提示"尚未合成" | **没有触发合成的按钮与逻辑**；产物不持久化到成片库目录 |
| core-engine | AgnesProvider 已有 Text/Image/Video 三通道+自动选模；FfmpegAssembler 有三级策略（concat-copy/归一化/分段导出），JVM 走命令行 ffmpeg | Android 端无命令行 ffmpeg，需要端上方案决策 |

## 三、功能分级清单

### P0 —— 本版本必须交付

#### P0-1 首页双模式入口
- **用户故事**：作为一个短剧创作者，我打开 App 后能一眼看到「AI 全托管」和「人工模式」两个大入口，这样我不想逐步点的时候直接把剧本丢给 AI 就完事。
- **验收标准**：
  1. 启动后默认页顶部呈现两张模式卡片（中文文案：「🤖 AI 全托管」/「✍️ 人工模式」）；点人工模式跳转现有项目页，原流程零改动。
  2. 记住上次选择的模式（下次启动直达该模式视图），可在设置中重置。
  3. :app:assembleDebug 通过。

#### P0-2 AI 全托管流水线 + 流式进度
- **用户故事**：作为懒人创作者，我在 AI 模式粘贴一段小说/剧本文本，点一下「一键成片」，就能看到一条实时滚动的任务日志流（提取资产 → 生成图像 → 质量审计 → 生成分镜 → 入队渲染），每个阶段成功/失败都即时推送上来，结束后分镜已生成且渲染已入队。
- **验收标准**：
  1. 输入框接受 ≥100 字文本；点击后按顺序自动执行五阶段，全程无需人工干预。
  2. 进度用 `StateFlow<List<ProgressEvent>>` 实现（枚举阶段 + 中文消息 + 时间戳），UI 以日志流形式实时滚动展示，不引入新库。
  3. 任一阶段失败：进度流标红显示失败原因，流程终止且可「重试该阶段」，已完成阶段结果保留不重复调用。
  4. 全程复用现有 AssetsViewModel/StoryboardViewModel/enqueueRender 接线；预算熔断规则照常生效。
  5. JVM 可跑的流水线编排逻辑有单测且真跑绿。

#### P0-3 成片合成接入 App 端
- **用户故事**：作为追更的作者，整集镜头全部 COMPLETED 后，我在成片库点「合成本集成片」，得到一个单一 mp4 文件，能直接在 App 内播放或系统分享。
- **验收标准**：
  1. 成片库每集卡片新增「合成本集成片」按钮，仅当该集所有镜 COMPLETED 时可用。
  2. 点击后后台合成（复用 FfmpegAssembler 策略降级链），进度可见，产物写入应用私有成片目录并记录元数据（集 ID、时长、文件大小、合成时间）。
  3. 合成完成后卡片变为「可播放 ✓」，支持 App 内播放器预览与 ACTION_SEND 分享。
  4. 合成失败给出明确错误信息，可重试。
  5. 端上 ffmpeg 方案由架构 Agent 决策（候选 a：`com.arthenica:ffmpeg-kit-full` Gradle 依赖；候选 b：服务端合成预留接口 + 端上引导），PRD 默认按 (a) 端上离线合成写验收，若定 (b) 则"播放"验收项顺延为"提交合成任务成功 + 完成后可播放"。

### P1 —— 本版本应交付

#### P1-1 DeepSeek 文本模型接入与设置页选择
- **用户故事**：作为对成本敏感的作者，我想在设置页把文本模型切到 DeepSeek（比 Agnes 默认便宜），切换后资产提取和 AI 分镜就走 DeepSeek，图像/视频仍走 Agnes。
- **验收标准**：
  1. 设置页新增「文本模型」区块，可单选 DeepSeek / Agnes 默认；DeepSeek 配置走 OpenAI 兼容（base_url=`https://api.deepseek.com/v1`，model=`deepseek-chat`），API Key 加密入 KeyVault。
  2. 提供「测试连通」按钮，成功/失败均有明确反馈。
  3. 切换保存后，新的 AI 资产提取/分镜请求实际路由到 DeepSeek（可用请求日志验证）；DeepSeek 不承担图像/视频通道。
  4. Key 为空或连通失败时，AI 全托管流程给出阻断提示而非静默失败。

### P2 —— 体验优化（时间富余再做）

#### P2-1 AI 模式进度流体验增强
- **用户故事**：作为围观 AI 干活的作者，我希望日志流有阶段图标/耗时统计，失败时一键复制日志去反馈。
- **验收标准**：每条 ProgressEvent 显示相对耗时；长按可复制全文；日志超过 500 条自动裁剪早期条目。

#### P2-2 成片库管理
- **用户故事**：作为囤了很多集的作者，我能在成片库看到每部片的文件大小/时长，删除不要的成片释放空间。
- **验收标准**：成片列表显示大小与时长；提供删除（二次确认）并清理文件。

#### P2-3 版本收尾
- versionCode+1 / versionName 1.4.0；更新 reports/ai-drama-dev-report.md 历史轮次记录。
